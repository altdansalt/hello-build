# redis

Redis **7.2.7** (the last fully BSD-licensed release line; see
[UPSTREAM](UPSTREAM)) under the seven-target interface
([ADR 0001](../docs/decisions/0001-seven-target-interface.md)). Sources are
fetched as `@redis_src` (sha256-pinned `http_archive` in MODULE.bazel); the
Bazel-native cc build is [redis.BUILD.bazel](redis.BUILD.bazel), injected
into that repo, and this package holds the interface and tests.

## Targets

| Target | Covers |
|---|---|
| `:legacy_build` | unmodified upstream `make MALLOC=libc` → redis-server, redis-cli, redis-benchmark |
| `:legacy_binary`, `:legacy_binary_cli` | run the legacy server / cli |
| `:legacy_test` | upstream tcl suite (10 units, ~30s) vs legacy binaries — **requires tclsh** |
| `:legacy_test_functional` | portable sh functional suite vs legacy binaries |
| `:bazel_build` | Bazel-native `cc_binary` build → redis-server, redis-cli |
| `:bazel_binary`, `:bazel_binary_cli` | run the Bazel server / cli |
| `:bazel_test` | same upstream tcl suite vs Bazel binaries — **requires tclsh** |
| `:bazel_test_functional` | same functional suite vs Bazel binaries |
| `:parity_test` | functional suite byte-identical on both builds + server case parity |
| `:parity_test_cli` | cli case parity |

Hosts without tclsh: `bazel test //redis:all --test_tag_filters=-requires-tclsh`.

## Upstream suite

- `:legacy_test` / `:bazel_test` run 10 units of upstream's tcl suite
  (`unit/type/*`, incr, expire, keyspace, auth, scripting — the list is
  `TCL_UNITS` in [BUILD.bazel](BUILD.bazel)) against the respective
  binaries, unchanged, via upstream's own `runtest` driver (~30s,
  `requires-tclsh`).
- Excluded: the `integration/*` units (replication, AOF, cluster) — slower
  and partly flaky-by-design (kill/restart loops); candidates for an opt-in
  `size = "enormous"` tier. The functional sh suite is ours and therefore
  *parity* evidence, not upstream coverage (hence the `*_functional` names).

## Build profile and configuration decisions

- **Profile:** upstream's default `make` optimization (`-O3 -flto=auto`, no
  `-DNDEBUG` — redis asserts stay live) is mirrored exactly in the Bazel
  copts/linkopts below; neither side uses Bazel's `-c opt` (which would add
  `-DNDEBUG` and compile asserts out, diverging from upstream — ADR 0008).

- **`MALLOC=libc` on both sides.** Upstream's default on Linux is bundled
  jemalloc, built by jemalloc's `configure`. Rather than teach the Bazel
  build to run that configure (or misrepresent parity by comparing a
  jemalloc server against a libc one), both builds use upstream's documented
  `MALLOC=libc` option. Cost: the parity claim covers the libc-allocator
  configuration, not the jemalloc default. Revisit if/when we Bazel-ify
  jemalloc.
- **`SOURCE_DATE_EPOCH=0` on both sides.** Upstream's `mkreleasehdr.sh`
  honors it; the build id (and its hash in `--version` output) becomes
  deterministic and *equal* across the two builds, so parity needs no
  output normalization at all.
- **Bazel build mirrors `make V=1` exactly.** Source lists in
  [srcs.bzl](srcs.bzl) are transcribed from the upstream link commands;
  copts/linkopts (including `-flto=auto`, `-O3`, `-rdynamic`) from the
  compile commands. Dep libraries (lua, hiredis, linenoise, hdr_histogram,
  fpconv) keep their upstream per-library flags.
- **`release.h`** is generated by running the unmodified upstream script in
  a genrule.
- Actions run without network (private loopback only, ADR 0006); the tcl
  suite's port probing therefore can't race other tests, and the legacy
  build provably downloads nothing.

## Parity evidence

- The 239-line functional suite transcript (every collection type, expiry,
  bit ops, error paths, embedded lua incl. cjson/struct/cmsgpack/bit,
  functions, `COMMAND COUNT`, stable INFO fields, fpconv float formatting)
  is **byte-identical** between legacy and Bazel builds, and passes.
- `--version`/`--help` for server and cli are byte-identical, including the
  build-id hash. **No normalization is applied anywhere.**
- The same 10-unit upstream tcl subset passes against both builds
  (`legacy_test` / `bazel_test`).

## Known gaps

- `redis-benchmark`, `redis-sentinel` (a symlink mode of the server binary
  upstream builds), and module support (`tests/modules`, *.so) are not in
  the Bazel build yet; the chosen tcl units don't need them.
- tcl `integration/*` units are not run (see "Upstream suite" above).
- Upstream default allocator (jemalloc) is not exercised (see above).
- The tcl suite needs host tclsh 8.5+ (tagged `requires-tclsh`).
